- commit مستندسازی وضعیت انتشار، پس از این بررسی push می‌شود و Pages را یک بار دیگر
  فقط با همان نسخهٔ ۰٫۴٫۰ بازسازی می‌کند.

برای انتشار، این پیش‌نیازها برقرار شدند:

1. مخزن با اجازهٔ صریح مالک عمومی شد (پلن رایگان Pages خصوصی ندارد).
2. Pages با منبع «GitHub Actions» فعال شد.

هرگز لینک را قبل از دیدن نتیجهٔ موفق `deploy-pages` اعلام نکنید. تغییرهای بعدی روی
`main` به‌صورت خودکار پس از سبزشدن همهٔ تست‌ها منتشر می‌شوند.

## workflowها

### `ci.yml`

با هر push به `main` و هر Pull Request اجرا می‌شود:

- `npm ci`
- `npm run lint`
- `npm run typecheck`
- `npm run test:ci`
- `npm run build`
- یک build اضافی با `VITE_BASE_PATH` مسیر مخزن، برای اطمینان از سازگاری با Pages.

مجوزها فقط `contents: read` است. یک concurrency گروهی اجراهای قدیمی‌تر همان ref را لغو
می‌کند.

### `deploy-pages.yml`

با push به `main` یا اجرای دستی:

1. job `build` همان lint/typecheck/test و تست مرورگری موبایل را اجرا می‌کند.
2. `actions/configure-pages` مسیر base واقعی سایت را استخراج می‌کند.
3. `npm run build` با `VITE_BASE_PATH` برابر خروجی `base_path` انجام می‌شود.
4. `npm run check:pages` بررسی می‌کند همهٔ ارجاع‌های محلی داخل `dist/index.html` با
   همان base شروع شوند و پوشهٔ `dist/assets` وجود داشته باشد.
5. `dist` به‌عنوان artifact استاندارد Pages آپلود می‌شود.
6. job `deploy` با environment `github-pages` و مجوزهای `pages: write` و
   `id-token: write` فقط artifact ساخته‌شده را منتشر می‌کند.
7. اگر هر مرحلهٔ قبلی شکست بخورد، deploy اجرا نمی‌شود.

هیچ secret، PAT، کلید API یا توکن اختصاصی در workflow لازم نیست. `GITHUB_TOKEN` با
حداقل مجوزهای لازم استفاده می‌شود و از force push یا بازنویسی تاریخچه استفاده نمی‌شود.

## مسیر base و GitHub Pages

Vite از تابع `resolveBase` در `src/config/basePath.ts` استفاده می‌کند:

- بدون متغیر محیطی: `./` (قابل استفاده روی هر میزبان استاتیک)
- با `VITE_BASE_PATH=/my-repo/`: `/my-repo/`
- مسیرها نرمال می‌شوند و URL کامل به‌عنوان base پذیرفته نمی‌شود.

در workflow انتشار، مسیر از خروجی configure-pages گرفته می‌شود؛ بنابراین نام مخزن در
کد تکرار نشده است و برای پروژهٔ `username.github.io` مسیر ریشه به‌درستی استفاده می‌شود.
همهٔ بافت‌ها، فونت و favicon از طریق import/Vite یا مسیر پردازش‌شدهٔ public بارگذاری
می‌شوند؛ هیچ URL مطلق خارجی در زمان اجرا لازم نیست.

## فعال‌سازی Pages (یک‌بار)

این مرحله برای این مخزن انجام شده است و برای مخزن جدید یا انتقال مالکیت تکرار می‌شود:

1. مخزن باید عمومی باشد یا پلن GitHub امکان Pages خصوصی را بدهد.
2. در GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. اگر محیط `github-pages` وجود ندارد، GitHub معمولاً در اولین اجرای موفق deploy آن را
   پیشنهاد/ایجاد می‌کند؛ در صورت نیاز آن را با نام `github-pages` بسازید.
4. تغییرات را روی `main` push کنید یا workflow را دستی اجرا کنید.
5. در تب Actions، اجرای موفق `Deploy GitHub Pages` را بررسی کنید و URL خروجی job deploy
   را باز کنید.

> `actions/configure-pages` با گزینهٔ `enablement: true` می‌تواند Pages را خودکار فعال
> کند، اما این گزینه به توکنی با دسترسی مدیریتی نیاز دارد و `GITHUB_TOKEN` معمولاً چنین
> دسترسی‌ای ندارد. بنابراین در این پروژه از فعال‌سازی خودکار استفاده نشده و فعال‌سازی
> یک‌باره در تنظیمات مخزن انجام می‌شود.

## منبع نقشه در زمان اجرا

از نسخهٔ ۰٫۴٫۰، نمای نزدیک زمین کاشی‌های OpenStreetMap را از
`https://tile.openstreetmap.org/{z}/{x}/{y}.png` می‌گیرد:

- بدون API key یا secret؛
- انتساب آشکار در UI؛
- فقط کاشی‌های ناحیهٔ دیده‌شده و پس از توقف دوربین (حداکثر ۱۶ کاشی visible در هر
  مجموعه)؛
- LOD بر اساس DPR واقعی، FOV، فاصله و پوشش viewport؛
- کش هفت‌روزه در Cache Storage با سقف ۱۲۰ ورودی؛
- بدون prefetch، bulk download یا استفادهٔ آفلاین؛
- درخواست‌های مجموعهٔ قبلی با تغییر نما لغو می‌شوند؛
- وابستگی نرم به OSM: اگر سرویس در دسترس نباشد، لایهٔ تصویر NASA/کرهٔ پایهٔ مات و UI
  باقی می‌مانند و پیام خطا نمایش داده می‌شود.

لایهٔ تصویر NASA بخشی از همان dist است و از مبدأ Pages با مسیر
`earth-detail/v1/{level}/{x}/{y}.webp` سرو می‌شود؛ این کاشی‌ها OSM نیستند، هیچ درخواست
خارجی/کلید لازم ندارند و در استارتاپ دانلود نمی‌شوند. `check:pages` باید پس از build
تأیید کند که صفحه و دارایی‌های بسته با base سازگارند؛ مسیر کاشی‌های تصویر در runtime از
`import.meta.env.BASE_URL` ساخته می‌شود.

GitHub Pages صفحه را با HTTPS و دامنهٔ ثابت سرو می‌کند؛ مرورگر Referer معتبر می‌فرستد
و پاسخ کاشی CORS را اجازه می‌دهد. هیچ تغییری در base path یا workflow لازم نیست.
سیاست OSM بهترین‌تلاش و بدون SLA است و می‌تواند تغییر کند؛ برای جایگزینی provider،
`src/geo/tiles/tileProvider.ts` نقطهٔ تغییر است.

## بررسی نسخهٔ منتشرشده روی گوشی

1. URL نهایی Pages را در مرورگر گوشی باز کنید (HTTPS است).
2. در حالت کاوش آزاد، چرخش/زوم و انتخاب ماه، خورشید و مریخ را آزمون کنید. نزدیک
   زمین، کره باید حتی هنگام بارگذاری/شکست کاشی مات بماند و زوم نباید از سطح عبور
   کند.
3. روشنایی روز/شب را با ساعت UTC بررسی کنید: نیم‌کرهٔ روز روشن و نیم‌کرهٔ شب با
   چراغ‌های شهر قابل‌تشخیص باشد. نزدیک‌شدن باید جزئیات NASA را از بافت پایه جدا کند
   و در حالت حداکثر، «بالاترین جزئیات تصویر» دیده شود. این نمایش تقریبی است و
   بافت پایه/تصویر به OSM وابسته نیستند.
4. به آسمان واقعی بروید؛ اجازهٔ مکان را درخواست کنید یا مختصات را دستی وارد کنید.
5. زمان را تغییر دهید و موقعیت خورشید/ماه/مریخ و وضعیت افق را بررسی کنید.
6. حسگر را جداگانه فعال کنید؛ وضعیت «فعال/نسبی/غیرفعال/پشتیبانی‌نشده» باید صادقانه
   نمایش داده شود. اگر جهت اشتباه بود، از کالیبراسیون دستی استفاده کنید.
7. در صورت وجود دوربین، لایهٔ دوربین را فعال کنید و پس از خروج، مطمئن شوید تصویر قطع
   می‌شود. درخواست مجوز دوربین باید مستقل از حسگر باشد.
8. در صورت ردکردن هر مجوز، برنامه باید پیام روشن بدهد و مسیر جایگزین (ورود دستی/چرخش
   آزاد) را حفظ کند. برای مکان، پیام کوتاه و دکمهٔ «تلاش دوباره» باید دیده شود.

## عیب‌یابی

| نشانه | بررسی |
| --- | --- |
| صفحهٔ سفید یا 404 برای فایل‌های JS/CSS | مقدار `base` با URL واقعی Pages هم‌خوان نیست؛ workflow و خروجی `configure-pages` را بررسی کنید. |
| خطای `Get Pages site failed` در configure-pages | Pages در تنظیمات فعال نیست یا منبع آن GitHub Actions نیست. |
| خطای مجوز در deploy | job باید `pages: write` و `id-token: write` داشته باشد و environment درست باشد. |
| رشتهٔ قدیمی بعد از انتشار | cache مرورگر؛ hard refresh یا بستن/بازکردن زبانه. |
| درخواست موقعیت نمایش داده نمی‌شود | صفحه باید HTTPS باشد؛ مجوز مرورگر/سیستم را بررسی کنید یا مختصات را دستی وارد کنید. |
| حسگر داده نمی‌دهد | ممکن است دستگاه حسگر نداشته باشد، iOS اجازه نداده باشد یا مرورگر رویداد absolute ندهد. وضعیت و پیام در برنامه نمایش داده می‌شود. |
| دوربین شروع نمی‌شود | HTTPS، مجوز دوربین، استفادهٔ انحصاری برنامهٔ دیگر یا نبود دوربین پسین را بررسی کنید. |
| لایهٔ دوربین با آسمان هم‌راستا نیست | FOV مرورگر قابل خواندن نیست؛ لغزندهٔ میدان دید را دستی تنظیم کنید. |

## مسیر انتشار جدید

اگر مخزن جابه‌جا یا نام آن تغییر کرد، استفاده از خروجی `configure-pages` باعث می‌شود
مسیر base خودکار به‌روز شود؛ نیازی به hardcode نام مخزن نیست. پس از تغییر visibility یا
مالکیت، Pages را دوباره در تنظیمات بررسی کنید.

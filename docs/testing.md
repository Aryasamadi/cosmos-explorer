# تست، اعتبارسنجی و کنترل کیفیت

## دستورها

```bash
npm run lint
npm run typecheck
npm run test        # حالت watch برای توسعه
npm run test:ci     # اجرای یک‌بارهٔ تست‌های Vitest
npm run test:e2e    # تست مرورگری موبایل با Playwright/Chrome
npm run build
VITE_BASE_PATH=/cosmos-explorer/ npm run build
VITE_BASE_PATH=/cosmos-explorer/ npm run check:pages
```

`npm run test:e2e` از Chrome نصب‌شده روی سیستم استفاده می‌کند (`channel: chrome`).
اگر Chrome نصب نباشد، می‌توانید `npx playwright install chromium` را اجرا کنید و
پیکربندی را به Chromium تغییر دهید؛ در GitHub Actions از Chrome نصب‌شدهٔ runner استفاده
می‌شود.

CI همین مراحل را پیش از هر انتشار اجرا می‌کند و علاوه بر آن یک build با
`VITE_BASE_PATH` مسیر GitHub Pages می‌سازد و با `npm run check:pages` بررسی می‌کند
همهٔ ارجاع‌های محلی دارایی‌ها با همان base شروع شوند. انتشار GitHub Pages فقط پس از
موفقیت lint، typecheck، تست، build و این بررسی انجام می‌شود.

## وضعیت اجرای فعلی

- **۸۰ تست Vitest** در ۱۵ فایل و **۱ تست مرورگری Playwright**، همه سبز
  (اجرا در ۲۰۲۶-۱۰-۲۲).
- `lint`: بدون خطا و بدون warning.
- `typecheck`: بدون خطا با TypeScript strict.
- `build`: موفق.
- انتشار GitHub Pages در ۲۰۲۶-۱۰-۲۲ با آدرس
  <https://aryasamadi.github.io/cosmos-explorer/> تأیید شد: HTTP 200، بدون خطای
  کنسول/شبکه در Chrome واقعی، viewport ۳۹۰×۸۴۴، بدون سرریز افقی.
- آزمون سخت‌افزاری واقعی روی گوشی انجام نشده است. آزمون‌های مرورگر با Chrome Headless و
  شبیه‌سازی حسگر/دوربین انجام شده‌اند.

## مرجع مستقل JPL Horizons

نمونه‌های منبع در `src/test/referencePositions.ts` ثبت شده‌اند. تنظیمات پرس‌وجو:

```text
format=text
EPHEM_TYPE=OBSERVER
CENTER=coord@399
COORD_TYPE=GEODETIC
REF_SYSTEM=ICRF
APPARENT=AIRLESS
QUANTITIES=4,20
```

این تنظیمات، آزیموت/ارتفاع ظاهری بدون شکست جو و برد را برای ناظر ژئودتیک می‌دهد.

### تلورانس‌ها

- آزیموت/ارتفاع: `< 0.02°`
- فاصلهٔ نسبی: `< 3×10⁻⁴`
- Polaris: اختلاف ارتفاع با عرض ناظر `< 1.5°` (به دلیل فاصلهٔ ۰٫۷۴ درجه‌ای از قطب)

این تلورانس‌ها برای نمایش آموزشی انتخاب شده‌اند و ادعای ناوبری دقیق نمی‌کنند. مقایسه
فقط پیاده‌سازی و یکپارچه‌سازی را می‌سنجد.

## آزمون مرورگر شبیه‌سازی‌شده

در تاریخ ۲۰۲۶-۱۰-۲۲ با Chrome Headless (نسخهٔ ۱۵۰) و viewport موبایل **۳۹۰×۸۴۴**
(devicePixelRatio=2، locale=fa-IR، timezone=Asia/Tehran) سناریوهای زیر اجرا شد:

1. بارگذاری کاوش آزاد، نمایش زمین، انتخاب ماه و بازشدن پنل اطلاعات.
2. تغییر به آسمان واقعی، ورود دستی مختصات تهران و نمایش snapshot علمی.
3. فعال‌سازی حسگر با رویدادهای شبیه‌سازی‌شدهٔ absolute و مشاهدهٔ وضعیت «حسگر روشن».
4. فعال‌سازی دوربین با دستگاه دوربین جعلی Chrome، نمایش video و سپس خاموش‌کردن آن.
5. تغییر زمان به یک لحظهٔ روز و مشاهدهٔ خورشید/مریخ و گرادیان روز.
6. بررسی نبود خطای کنسول و نبود سرریز افقی صفحه.

بخشی از این سناریوها اکنون در `e2e/mobile.spec.ts` به‌صورت خودکار و در CI اجرا می‌شوند
(جریان پایهٔ رابط کاربری و ورود دستی مکان). سناریوهای حسگر و دوربین شبیه‌سازی‌شده در
این نسخه فقط به‌صورت بررسی مرورگری دستی ثبت شده‌اند.

این آزمون‌ها **آزمون گوشی واقعی نیستند** و نمی‌توانند دقت قطب‌نما، جهت صفحه،
کالیبراسیون دوربین یا رفتار iOS Safari را تأیید کنند. هیچ ادعای تأیید سخت‌افزاری در
README یا رابط کاربری مطرح نشده است.

## محدودیت‌های تست فعلی

- WebGL در jsdom اجرا نمی‌شود؛ تست‌های UI عمداً مسیر fallback را می‌سنجند. صحنه‌های
  Three.js با آزمون مرورگر واقعی (شبیه‌سازی‌شده) بررسی شده‌اند، نه در Vitest.
- آزمون Playwright فقط جریان پایهٔ UI را در Chrome پوشش می‌دهد؛ سناریوهای حساس به
  سخت‌افزار (حسگر، دوربین، iOS) در آن به‌صورت خودکار شبیه‌سازی نمی‌شوند.
- هیچ benchmark رسمی FPS، مصرف حافظه یا باتری روی دستگاه‌های مختلف انجام نشده است.
- دقت موقعیت ماه/سیارات فقط در نمونه‌های JPL ثبت‌شده سنجیده شده است؛ پوشش جهانی
  ادعا نمی‌شود.
- رفتار iOS Safari برای `requestPermission` و `webkitCompassHeading` با unit test و
  شبیه‌سازی منطقی بررسی شده، نه روی دستگاه واقعی.
- متن‌های فارسی و چیدمان با بررسی بصری در مرورگر ارزیابی شده‌اند؛ آزمون خودکار a11y
  کامل وجود ندارد.

## افزودن تست

- منطق خالص را در همان پوشهٔ ماژول با `*.test.ts` قرار دهید.
- برای محاسبات نجومی، نمونهٔ مرجع بیرونی (در صورت وجود) و تلورانس را در همان فایل ثبت
  کنید؛ تست را فقط برای سبز شدن ضعیف نکنید.
- برای تست UI، `@testing-library/react` و `userEvent` استفاده کنید و به CSS یا WebGL
  واقعی وابسته نشوید.
- هر تغییر در کاتالوگ باید تست‌های یکتایی شناسه، منبع و اعتبار عددی را حفظ کند.

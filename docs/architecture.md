# معماری COSMOS EXPLORER

## هدف معماری

هدف این نسخه، ساخت یک هستهٔ واقعی و قابل گسترش است که سه مرز مهم را حفظ می‌کند:

1. **علم از نمایش جدا است.** مقادیر و مختصات نجومی در `src/astronomy` و `src/catalog`
   زندگی می‌کنند و به React یا Three.js وابسته نیستند.
2. **رابط کاربری از جزئیات موتور سه‌بعدی جدا است.** React داده و فرمان می‌دهد؛
   کلاس‌های `FreeExploreScene` و `SkyScene` مالک چرخهٔ WebGL هستند.
3. **حسگرها از رابط جدا هستند.** ریاضیات جهت‌یابی در `src/sensors/orientationMath.ts` و
   مدیریت مجوز/رویداد در `DeviceOrientationService` قرار دارد و با React مخلوط نشده است.

## نقشهٔ ماژول‌ها

```text
.github/workflows/   CI و انتشار GitHub Pages
docs/                معماری، مدل نجومی، تست، انتشار و ADRها
scripts/             بررسی خروجی build برای base path صفحات
public/              favicon و دارایی‌های عمومی ثابت
src/
├── app/             وضعیت متمرکز، ترکیب صفحه، قالب‌بندی فارسی
├── catalog/         کاتالوگ اجرام، داده‌های علمی، منابع و اعتبار دارایی‌ها
├── astronomy/       مختصات، ephemeris، اعتبارسنجی و قراردادهای علمی
├── sensors/         ریاضیات quaternion دستگاه و سرویس رویداد جهت‌یابی
├── engine/          پیاده‌سازی Three.js برای صحنهٔ آزاد و آسمان واقعی
├── hooks/           آداپتورهای React برای WebGL، حسگر و دوربین
├── features/        رابط کاربری کاوش آزاد، آسمان، پنل اطلاعات، تنظیمات
├── components/      اجزای عمومی رابط (Sheet، Switch، Notice، آیکون‌ها)
├── config/          نسخه، مسیر base، متن مقیاس نمایشی
├── styles/          توکن‌های طراحی، چیدمان، پنل‌ها و استایل آسمان
├── assets/          بافت‌های محلی سیارات و قلم وزیرمتن
└── test/            راه‌اندازی تست و نمونه‌های مرجع JPL
```

پوشه‌های خالی و لایه‌های بدون مصرف ساخته نشده‌اند. مثلاً `engine/scene`،
`engine/camera` و `engine/materials` به زیرماژول‌های واقعی فعلی تقسیم شده‌اند، نه به
پوشه‌های تشریفاتی.

## مرزها و مسئولیت‌ها

### `src/catalog`

- `bodies.ts`: زمین، ماه، خورشید، مریخ و ۱۲ ستارهٔ درخشان. هر ادعای عددی `dataType`
  (اندازه‌گیری‌شده، میانگین، بازه، مؤثر، تقریبی) و `sourceIds` دارد.
- `sources.ts`: منابع داده مانند NASA Fact Sheets، SIMBAD و Astronomy Engine.
- `credits.ts`: مجوز و انتساب دارایی‌های تصویری و قلم.
- این لایه هیچ importی از React یا Three.js ندارد.

### `src/astronomy`

- `coordinates/angles.ts`: نرمال‌سازی زاویه، ساعت و clamp با ردکردن NaN/Infinity.
- `coordinates/horizontal.ts`: تبدیل مختصات استواییِ تاریخ به ارتفاع/سمت با فرمول
  ساعت زاویه‌ای. قرارداد: آزیموت از شمال و در جهت شرق، ارتفاع مثبت بالای افق.
- `coordinates/projection.ts`: نگاشت ارتفاع/سمت به دستگاه صحنه:
  `+X = شرق`, `+Y = سمت‌الرأس`, `-Z = شمال`.
- `ephemeris/skySnapshot.ts`: ساخت عکس فوری آسمان با Astronomy Engine برای خورشید،
  ماه، مریخ و ستارگان ثابت؛ شامل فاصله، قدر ظاهری، درصد روشنایی ماه، وضعیت افق و
  طبقه‌بندی روز/گرگ‌ومیش.
- `validation/input.ts`: اعتبارسنجی مکان، ارتفاع، تاریخ و ارقام فارسی.

این لایه از دامنه‌های DOM، React و Three.js مستقل است؛ تنها وابستگی خارجی آن
`astronomy-engine` است.

### `src/sensors`

- `orientationMath.ts`: ساخت quaternion دوربین از زاویه‌های W3C، اصلاح جهت صفحه،
  تبدیل به north/east/up و کالیبراسیون heading.
- `DeviceOrientationService.ts`: درخواست اجازه (از جمله iOS)، گوش‌دادن به
  `deviceorientationabsolute`/`deviceorientation`، timeout، وضعیت unavailable،
  مدیریت برگشت از پس‌زمینه و پاک‌سازی listenerها.
- وضعیت «مطلق/نسبی» صریح است. اگر مرجع شمال حقیقی نباشد، UI آن را پنهان نمی‌کند.

### `src/engine`

- `shared/`: تشخیص WebGL، حلقهٔ رندر قابل توقف در پس‌زمینه، آزادسازی geometry/material/texture.
- `free/FreeExploreScene.ts`:
  - مالک renderer، صحنه، دوربین، OrbitControls و چرخهٔ نابودی.
  - focus نرم دوربین، انتخاب با raycast و بازگشت به نمای کلی.
  - context lost/restore و pause هنگام hidden.
- `free/solarSystem.ts`: ساخت زمین/ماه/خورشید/مریخ، جوّ نمایشی، نورپردازی و ستاره‌های
  پس‌زمینه. مقیاس نمایشی فقط در همین لایه تعریف می‌شود.
- `sky/SkyScene.ts`:
  - گنبد و شبکهٔ ارتفاع/سمت، نشانه‌ها و برچسب‌های CSS2D.
  - چرخش با حسگر یا free-look دستی، pinch/wheel برای FOV، انتخاب با raycast.
  - مالک `CSS2DRenderer`، context loss و cleanup.
- `sky/skyObjects.ts`: نشانه‌های تصویری خورشید/ماه/مریخ/ستاره‌ها. نشانه‌ها عمداً ساده‌اند
  و ادعای تصویر واقعی یا اندازهٔ زاویه‌ای دقیق ندارند.
- `sky/skyDome.ts` و `sky/skyGrid.ts`: گرادیان سمبولیک روز/شب و شبکهٔ مختصات محلی.

UI هرگز مستقیم به `THREE` یا WebGL دسترسی ندارد؛ از طریق کلاس‌های صحنه و refها فرمان
می‌دهد. این اجازه می‌دهد تست‌های UI بدون WebGL هم اجرا شوند.

### `src/app` و `src/features`

- `appState.ts` یک reducer خالص است: حالت (`free`/`sky`)، جرم انتخاب‌شده، بازبودن پنل و
  حالت کم‌مصرف. تغییر حالت جرم نامعتبر را با گزینهٔ معتبر جایگزین می‌کند.
- `AppStateContext.ts` فقط context و hookهای آن را دارد؛ `AppStateProvider.tsx` فقط
  provider است تا Fast Refresh سالم بماند.
- `FreeExploreMode` چرخهٔ ساخت/نابودی صحنه را با ref callback مدیریت می‌کند (React 19
  cleanup) و حالت loading/error/context lost را نشان می‌دهد.
- `SkyMode` مالک مکان، زمان، تنظیمات، مجوزها و هماهنگی snapshot با صحنه است.
- `SkyViewport` فقط آداپتور میان React و `SkyScene` است؛ ساخت صحنه، اعمال snapshot،
  grid، FOV و حالت دوربین را مدیریت می‌کند.
- `CelestialInfoPanel` نمایش داده‌های علمی و منبع را از کاتالوگ می‌گیرد و هیچ محاسبهٔ
  نجومی انجام نمی‌دهد.

## جریان داده در حالت آسمان

```text
موقعیت (GPS/دستی) + زمان (اکنون/انتخابی)
                │
                ▼
      computeSkySnapshot()  ←  Astronomy Engine
                │
        ┌───────┴─────────┐
        ▼                 ▼
  React (HUD/پنل)     SkyScene.updateSnapshot()
                          │
                          ▼
                 موقعیت نشانه‌ها، گنبد، شبکه، برچسب‌ها

رویداد حسگر → orientation math → quaternion دوربین → SkyScene
درخواست دوربین → getUserMedia → <video> پشت canvas شفاف
```

- محاسبات موقعیت حداکثر یک بار در ثانیه (هنگام زمان زنده) اجرا می‌شوند؛ نه در هر فریم.
- دادهٔ حسگر در نرخ رویداد به موتور می‌رود و React را در هر فریم دوباره رندر نمی‌کند.
- ورودی‌های مکانی و زمانی معتبر نشده وارد محاسبه نمی‌شوند.

## چرخهٔ منابع و پایداری

- هر صحنه یک renderer و یک loop دارد؛ هنگام خروج، loop متوقف، listenerها حذف و
  texture/geometry/material آزاد می‌شوند.
- `RenderLoop` هنگام `document.hidden` متوقف و با بازگشت ادامه می‌یابد.
- `pixelRatio` به ۲ محدود و در حالت کم‌مصرف به ۱٫۲۵ کاهش می‌یابد.
- خطای WebGL یا از دست رفتن context به رابط قابل‌فهم تبدیل می‌شود؛ برنامه crash نمی‌کند.
- جریان دوربین با `track.stop()` آزاد می‌شود و پس از بازگشت از پس‌زمینه وضعیت پخش دوباره
  بررسی می‌شود.

## مقیاس نمایشی و مسیر توسعه

- زمین = ۱ واحد شعاع.
- ماه = ۰٫۲۷ واحد در فاصلهٔ ~۵٫۸ واحد.
- خورشید = ۳٫۲ واحد در فاصلهٔ ~۳۳ واحد.
- مریخ = ۰٫۵۳ واحد در فاصلهٔ ~۱۸ واحد.

این اعداد **مقیاس علمی نیستند** و فقط برای دیدن‌پذیری انتخاب شده‌اند. اطلاعات علمی از
کاتالوگ خوانده می‌شود.

برای توسعهٔ آینده:

1. جرم جدید: یک entry در `catalog/bodies.ts` + نگاشت در `ephemeris` + presentation در موتور.
2. ستارگان بیشتر: کاتالوگ J2000 با منبع/مجوز روشن؛ محاسبه با همان پیش‌روی و قرارداد
   مختصات فعلی.
3. منظومهٔ شمسی گسترده: نمایش مقیاس‌های چندگانه و در صورت نیاز floating origin؛ مقیاس
   نمایشی باید همچنان از مدل علمی جدا بماند.
4. اجرام عمق آسمان: لایهٔ کاتالوگ مستقل و انتخاب/برچسب‌گذاری بر اساس فاصله و روشنایی.
5. فرود مجازی: یک ماژول `surface` با دوربین/کنترل مستقل؛ نباید مختصات علمی را با نمای
   سطحی مخلوط کند.

## وابستگی‌های مجاز

در این مرحله هیچ backend، دیتابیس، احراز هویت، API پولی یا کلید مخفی در معماری وجود ندارد.
تنها ارتباط شبکه‌ای در زمان اجرا، بازکردن لینک منابع توسط کاربر است. GitHub Pages فقط
میزبانی فایل‌های استاتیک است.

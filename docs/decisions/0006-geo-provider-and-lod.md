# ADR 0006 — OSM raster tiles و LOD کرهٔ Three.js

- وضعیت: پذیرفته‌شده
- تاریخ: ۲۰۲۶-۱۰-۲۲

## زمینه

نسخهٔ قبلی زمین فقط یک بافت ثابت داشت، بدون مکان، مختصات یا دادهٔ جغرافیایی واقعی. این
مأموریت خواستار جغرافیای واقعی، مکان دقیق‌تر و LOD پیش‌رونده با محدودیت GitHub Pages و
بدون هزینه/کلید بود. MapLibre، کاشی‌های OSM، داده‌های عمومی و کاشی‌های تجاری بررسی شدند.

## تصمیم

1. **کرهٔ Three.js حفظ می‌شود.** رابط اصلی و دیگر اجرام تغییر معماری نمی‌دهند.
2. **کاشی رستری OpenStreetMap Standard** منبع پایهٔ جزئیات جغرافیایی است؛ بدون کلید،
   با انتساب آشکار، فقط برای ناحیهٔ دیده‌شده و با کش هفت‌روزه.
3. یک `RasterTileProvider` مستقل از UI تعریف می‌شود تا تعویض منبع در آینده ساده باشد.
4. LOD محدود و camera-driven است: حداکثر شبکهٔ ۳×۳، حداکثر ۹ کاشی، پس از توقف دوربین؛
   کاشی‌های Web Mercator با هندسه و UV درست به کره نگاشت می‌شوند.
5. نشانگر مکان و دایرهٔ دقت، فرزند گروه چرخش زمین هستند؛ قرارداد frame محلی و UV کره
   با تست هندسی ثابت شده است.
6. چرخش نمایشی خودکار زمین حذف شد تا نشانگر/کاشی از بافت drift نکند.
7. MapLibre در این فاز استفاده نشد: رندر دوم، مدل تعامل جداگانه و افزایش قابل توجه JS
   بدون نیاز اثبات‌شده در معماری فعلی. یک flat map اختیاری نیز در محدودهٔ این فاز نبود.

## دلیل

- OSM تنها گزینهٔ بررسی‌شدهٔ بدون کلید بود که هم‌زمان کشور، شهر، جاده و برچسب واقعی
  می‌دهد و شرایط استفادهٔ عمومی قابل استناد دارد.
- Three.js از قبل مالک دوربین/نورپردازی/دیگر اجرام است؛ افزودن رندر دوم معماری را
  ناهمگون می‌کرد.
- LOD کوچک و بدون prefetch با سیاست کاشی OSM سازگارتر و با حافظهٔ موبایل سازگارتر است.

## پیامدها

- نقشه کارتوگرافی است، نه تصویر ماهواره‌ای.
- جزئیات موتور تا z14 عملی است؛ منبع تا z19 می‌تواند برود. این شکاف مستند شده است.
- نمای پایه به شبکه وابسته نیست؛ اگر کاشی‌ها شکست بخورند، برنامه با پیام روشن ادامه
  می‌دهد.
- درخواست کاشی محدودهٔ تقریبی نما را برای OSM آشکار می‌کند؛ این موضوع در رابط و
  مستندات تصریح شده است.
- در آینده، provider جایگزین یا flat map می‌تواند بدون تغییر کاتالوگ/آسمان اضافه شود.
